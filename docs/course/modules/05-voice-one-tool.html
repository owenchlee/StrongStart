Voice In, Voice Out

How a parent's spoken answer, a staff member's dictated email and every Listen button come from the same two API calls, and why each outside service plays exactly one part.

One tool per job

On the feedback page a parent can tap Listen to hear each question read aloud, or tap Record your answer and just talk. Staff can tap a microphone in any text box on the dashboard. All of it is the same two API calls: speech-to-text and text-to-speech.

Picture the outside services as an orchestra where every instrument plays one part. No two instruments play the same line, and if one is missing the piece still plays, just quieter.

🎤

ElevenLabs: all audio

Every recording becomes words, every question becomes a voice. Nobody else in the project touches sound.

🧠

Gemini: all thinking

Reads handwriting, turns a transcript into fields, translates, summarises and tidies dictated emails. One brain, many tasks.

📷

Cloudinary: all images

Stores every photographed paper form and hands back a link. It never reads the form; that is Gemini's part.

🎵

Tiger Data: the one score

The single database everyone reads from. Nothing is copied into a second system, so nothing can drift out of tune.

📝
The rule, as written in WORKLOAD.md

"No two tools do the same job, and no data is copied into two databases." Sponsors reward depth over breadth, and one tool per job means there is never a second copy to fall out of sync.

Say it once, keep the MP3

Every program has the same handful of questions, so reading them aloud thousands of times would be paying ElevenLabs to repeat itself. Instead the server keeps a cache: the first time a question is spoken, the MP3 is saved to disk, and every later request just reads the file.

File: src/elevenlabs.js, lines 40–44, inside textToSpeech
CODE 

  const model = process.env.ELEVENLABS_TTS_MODEL || 'eleven_multilingual_v2';
  const hash = createHash('sha256').update(JSON.stringify([text, lang, voice, model])).digest('hex');
  const dir = process.env.TTS_CACHE_DIR || join('data', 'tts-cache');
  const file = join(dir, `${hash}.mp3`);
  if (existsSync(file)) return readFileSync(file);
PLAIN ENGLISH

Pick which ElevenLabs voice model to use. An environment variable can override it; otherwise use the multilingual one.

Make a fingerprint of this exact request. Bundle the text, language, voice and model into JSON, then run it through SHA-256 to get a hash.

Decide where cached audio lives. Default is a folder called data/tts-cache.

The file name is the fingerprint plus .mp3. Same question, same language, same voice means the same file name every time.

If that file already exists, hand it back straight away. ElevenLabs is never called for a question we have already heard.

Now the other side of the conversation: what the feedback page does when it taps Listen and the server answers 503.

File: public/feedback.html, lines 56–59, inside the Listen button handler
CODE 

  try {
    const r = await fetch(`/api/tts?lang=${encodeURIComponent(lang)}&text=${encodeURIComponent(text.slice(0, 300))}`);
    if (r.status === 503) { document.querySelectorAll('.listen').forEach((x) => x.hidden = true); return; }
    if (!r.ok) throw new Error();
PLAIN ENGLISH

Open a safety net with try, so a failure here cannot break the rest of the form.

Ask our own server for audio using fetch, passing the language and the first 300 characters of the question. await pauses until the reply arrives.

If the status code is 503, the server has no ElevenLabs key. Hide every Listen button on the page and stop; no error is shown.

Any other failure is thrown to the catch block, which simply gives up on this one playback.

💡
Design for the missing key

Every optional service here answers 503 Service Unavailable when unconfigured, and the page simply hides the feature. This is why npm test runs with no keys at all.

Voice becomes the same row as a photo

In Module 4 a photographed form went through Gemini to become rating, most_valued and suggestions. A spoken answer goes through the same Gemini structuring, so the feedback table never needs to know how the answer arrived.

📷

Paper form

Photo → Cloudinary stores it → Gemini reads the handwriting → structured fields. Source: photo.

🎤

Spoken answer

Recording → ElevenLabs writes the transcript → Gemini structures it → the same fields. Source: voice.

🎵

One feedback table

Both land as one row with a source column. Reports, trends and the review queue treat them identically.

The review rule for voice is simple: no usable rating, or no comments, means a human should look. The raw transcript is always kept in audio_transcript so that human can fix it without asking the parent to speak again.

File: src/routes/voice.js, lines 59–62; transcript came back from ElevenLabs speech-to-text
CODE 

  let s = null;
  try { s = ai.structureFeedbackText ? await ai.structureFeedbackText(transcript) : null; } catch (e) { console.error('[voice] structuring failed:', e.message); }
  const rating = Number.isFinite(Number(s?.rating)) && s?.rating != null ? Math.round(Number(s.rating)) : null;
  const weak = !s || rating == null || rating < 1 || rating > 5 || (!s.most_valued && !s.suggestions);
PLAIN ENGLISH

Start with an empty result, s, in case Gemini never answers.

If the AI module offers structuring, ask Gemini to turn the transcript into fields. If that fails for any reason, write a note in the server log and carry on with s still empty. The parent's recording is never lost because the AI hiccupped.

Pull out the rating only if it is a real number. Round it to a whole star; otherwise leave it as null.

Decide if this answer is weak: Gemini gave nothing, the rating is missing or outside 1 to 5, or there is neither a most-valued comment nor a suggestion. A weak answer sets the flag that puts it in the review queue.

Dictate anywhere, tidy with AI

The staff side gets the same instrument. One small script adds a microphone to every text box on the dashboard, and the first three lines of that file are its own instruction manual.

File: public/dictate.js, lines 1–3
CODE 

// Voice typing: adds a mic button to the bottom-left of every text box. Tap to record, tap again to stop;
// the audio is transcribed by ElevenLabs (POST /api/transcribe) and inserted where the cursor was.
// Opt a field out with data-nodictate (on the field or any ancestor).
PLAIN ENGLISH

A comment explaining the feature: a mic button appears in every text box, and tapping toggles recording.

The recording is sent with a POST to one endpoint, ElevenLabs transcribes it, and the words land where the typing cursor was. The same speech-to-text call the parents use.

Any box can refuse the mic by carrying a data attribute, so password fields and search boxes stay quiet.

Dictated email drafts come out rambling, so staff can ask Gemini to tidy them. Rather than wait for the whole polished email, the server streams it word by word as Gemini writes.

File: src/routes/compose.js, lines 63–66, inside POST /api/compose/polish-stream
CODE 

    const out = await ai.polishEmailStream(text, { recipientName: fac?.name || '' }, (soFar) => {
      if (!started) { started = true; res.setHeader('Content-Type', 'text/plain; charset=utf-8'); res.setHeader('Cache-Control', 'no-store'); }
      res.write(soFar.slice(last.length)); last = soFar;
    });
PLAIN ENGLISH

Ask Gemini to polish the text, telling it the facilitator's name if we know it. The third thing we pass is a callback that runs every time more words exist.

On the very first chunk, tell the browser what is coming: plain text in utf-8, via an HTTP header. The second header says do not keep a copy, since every draft is different.

Send only the new words since last time, then remember how far we got. The dashboard shows each piece as it lands.

End of the callback. When Gemini finishes, out holds the complete polished email.

One more speed trick lives at the end of that same AI function. Gemini can spend time thinking before it writes; for a tidy-up that is wasted seconds, so it is switched off, with a fallback in case the model refuses.

File: src/ai.js, lines 181–184, end of polishEmailStream
CODE 

  let out;
  try { out = await run({ thinkingConfig: { thinkingBudget: 0 } }); }
  catch (e) { out = await run({}); } // model may not accept the thinking setting
  return out || null;
PLAIN ENGLISH

Make space for the answer.

First attempt: run Gemini with its thinking budget set to zero, so it starts writing immediately.

If the model rejects that setting, try again with plain defaults. Slower, but it still works.

Hand back whatever came out, or null if nothing did, so the caller can fall back to the original text.
