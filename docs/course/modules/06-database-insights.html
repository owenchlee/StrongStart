The database and insights

PGlite on your laptop, Tiger Data in the cloud: the same seeds, two kinds of soil.

Two soils, one seed

Module 5 ended with every source becoming the same feedback row. This module shows where that row actually lives: in a database, and there are two of them to choose from.

Run npm install && npm run dev and the app is up with a real Postgres inside the Node.js process: no Docker, no account. Set one environment variable and the identical code runs on Tiger Data.

Think of the SQL as the seed. PGlite is a pot on the windowsill; Tiger Data is a field. Same seeds, same growth, two soils.

🪴

The windowsill pot: PGlite

In-process Postgres that grows the instant you start the app. It is in-memory by default (reset on restart) unless you set PGLITE_DIR to keep it on disk.

npm run devzero setup
PGLITE_DIRoptional: keep the pot between restarts
npm testevery test runs on a fresh pot
🌾

The field: Tiger Data

Hosted Postgres reached over the network with SSL. When the TimescaleDB extension is available, the same seeds also grow faster trend charts.

TIGER_DATABASE_URLthe one variable that picks the field
sslencrypted connection
timescaledbused when present, ignored when not

One interface for both

Both drivers get wrapped so every route in the app talks to the database through the same four functions. No route ever knows which soil it is standing in.

📋
query(sql, params)

Ask a question, get back many rows: every order, every feedback response for a chart.

🎯
one(sql, params)

Ask a question, get back just the first row: the one program behind this token.

✍️
run(sql, params)

Change something and get back the rows plus a rowCount of how many were touched.

🔒
tx(async fn)

A transaction: several changes that all succeed or all roll back. Nothing half-done is ever saved.

A schema that upgrades itself

The schema is one block of SQL that runs every time the app starts. Every statement is written so that running it against a database that already has the table or column does nothing.

Here is how the token column was added to programs after the first version shipped. A brand-new pot and a six-month-old field both end up identical.

PLAIN ENGLISH

A note to humans: these lines exist for databases that were created before this column did.

Give inbound emails a link to a partner, if they do not have one yet. If the partner is deleted, blank the link rather than failing.

Give programs a token column, if it is not there yet. Right now it is empty for old rows.

Backfill: every program without a token gets a fresh random UUID with the dashes removed.

From now on, new programs get a random token automatically.

And no program may ever have an empty token (safe now, because we just filled them all).

Build a unique index so token lookups are fast and no two programs can share one, if the index is not there yet.

💡
Idempotent

Idempotent means: running it twice is the same as running it once. That is what lets the app create or upgrade the database on every start with no migration tool. Sow the same seeds in the same bed twice and you still get one plant per spot.

Reports that are safe to open in Excel

For funders, programReport in src/report.js turns the feedback rows into four numbers and asks Gemini for a 3–4 sentence summary. The same rows can also be exported as CSV.

recommend %share of parents who would recommend the program

A CSV cell is just text, but a parent comment is text we did not write. One small function makes every cell safe before it reaches a spreadsheet.

src/report.js · lines 41–47
CODE 

/** One CSV cell: neutralises spreadsheet formulas (=, +, -, @, tab, CR prefixes) and quotes safely. */
export function csvCell(v) {
  if (v == null) return '';
  if (v instanceof Date) v = v.toISOString();
  let s = String(v);
  if (/^[=+\-@\t\r]/.test(s)) s = "'" + s;
  return /[",\r\n]/.test(s) ? `"${s.replace(/"/g, '""')}"` : s;
PLAIN ENGLISH

The promise this function makes: one safe cell, formulas disarmed, quotes handled.

Take any value (a number, a date, a parent comment) and return the text to put in the file.

Missing values (null) become an empty cell.

Dates become the standard 2026-11-07T... text form so every spreadsheet reads them the same way.

Everything else becomes plain text.

If the text starts with =, +, -, @, a tab or a carriage return (a regex check), put a single quote in front so a spreadsheet treats it as words, not a formula.

If it contains a comma, quote mark or line break, wrap it in quotes and double any inner quotes, the standard CSV rule. Otherwise return it as is.

⚠️
CSV injection

CSV injection: a cell starting with = or + runs as a formula when opened in a spreadsheet. Prefixing a quote neutralises it, so a mischievous parent comment can never execute on a funder laptop.

Tests that boot the real thing

Because the pot is in-process, npm test does not need a test database, a mock, or an account. It starts the actual server on in-memory PGlite and walks the whole order → feedback → report loop in seconds.

The first thing the smoke test does is remove every outside API key, so the app has to prove it works with no AI, no image host and no email.

In other tests, Gemini itself is injected as a fake, so the code that handles an AI answer is tested too, with zero spend. Three questions you will be asked, and the short answer to each:

🌾

Why Tiger Data?

Hosted Postgres we never administer, with TimescaleDB so trend charts stay fast as feedback grows. The same SQL runs on a laptop with no account, so there is no second codebase.

🧪

How do you test?

npm test boots the real server on in-memory PGlite with every API key deleted. One smoke test walks email to report in seconds.

🔁

How do you migrate?

We do not keep migration files. The schema is idempotent SQL that runs on every start, creating what is missing and adding columns to old databases in place.
