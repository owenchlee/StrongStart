The switchboard

Picture an old telephone switchboard. One operator takes every incoming call, checks a few things, then patches it through to the right department.

In our code the operator is src/server.js, a call is an HTTP request, and each department is a router file in src/routes/. Here is the operator's whole script.

File: src/server.js, lines 16 to 25
CODE 

export const app = express();
// Behind a reverse proxy (Caddy, etc.) the client IP comes from X-Forwarded-For; needed for per-IP rate limits.
if (process.env.TRUST_PROXY) app.set('trust proxy', /^\d+$/.test(process.env.TRUST_PROXY) ? Number(process.env.TRUST_PROXY) : process.env.TRUST_PROXY === 'true' ? 1 : process.env.TRUST_PROXY);
else if ((process.env.BASE_URL || '').startsWith('https:')) app.set('trust proxy', 1);
app.use(express.json({ limit: '1mb' }));
app.use(express.urlencoded({ extended: false })); // inbound-email webhooks often post form data
app.use(auth);        // /auth/*, /api/me: must come before the gate
app.use(requireStaff); // default-deny for the dashboard page and /api (before static serves index.html)
app.use(express.static('public'));
app.use(orders, feedback, dashboard, voice, compose, partners, programsRouter, trainingRouter, resourcesRouter, meetRouter);
PLAIN ENGLISH

Build the switchboard: one Express app that every request passes through. Exporting it lets the test scripts boot the very same app.

A note for readers: when the site sits behind a reverse proxy, the caller's real IP address arrives inside a header.

If the TRUST_PROXY environment variable is set, tell Express how many proxies to trust so the per-caller rate limit counts the right address.

Otherwise, if the public address starts with https, assume exactly one proxy stands in front.

Checkpoint 1: if the call carries JSON, unpack it, but refuse anything larger than 1 MB.

Checkpoint 2: also unpack old-fashioned form data, because inbound-email webhooks send it that way.

Checkpoint 3: the sign-in desk. It answers /auth/* and /api/me and has to sit before the gate.

Checkpoint 4: the gate. Anything not on the public allow-list needs a staff login. Module 3 is all about this one line.

Checkpoint 5: hand out the static files in public/ to anyone who got this far.

Finally, patch the call through to the ten departments. Each router only answers the addresses it knows; the rest pass it along.

💡
Order matters in Express

Each app.use is a checkpoint the request passes in sequence. Engineers call these middleware. Move the gate below the static files and the dashboard page would be served to strangers.

How a page talks to the server

There is no framework on the dashboard. Every tab is an async function that calls j('/api/...'), gets JSON back, and writes HTML into a section of the page.

The whole conversation with the server runs through one tiny helper at the top of index.html.

File: public/index.html, lines 26 to 32
CODE 

const j = (u, o) => fetch(u, o).then(async (r) => {
  if (r.status === 401) { location.href = '/login.html'; throw new Error('signed out'); }
  const body = await r.json().catch(() => ({}));
  if (!r.ok && !body.error) body.error = 'Request failed (' + r.status + ')';
  return body;
});
const jsonPost = (u, b, method = 'POST') => j(u, { method, headers: { 'Content-Type': 'application/json' }, body: JSON.stringify(b || {}) });
PLAIN ENGLISH

Define j, the helper every tab uses: fetch a URL from the API, then wait for the reply.

If the server answers status 401 (not signed in), send the browser to the login page and stop right there.

Read the reply as JSON. If it is not JSON at all, fall back to an empty object instead of crashing the tab.

If the server failed but gave no message, make one from the status code. This is the Request failed (500) text staff sometimes see.

Hand the parsed reply back to whichever tab asked for it.

End of the helper.

jsonPost wraps j for sending data: it sets the method to POST, labels the body as JSON and turns the object into text.

Before any of that data touches the database, it passes through the drawer of common tools. These tiny helper functions clean every input, and every router uses them instead of rolling its own.

File: src/util.js, lines 4 to 11
CODE 

export const BASE_URL = (process.env.BASE_URL || 'http://localhost:3000').replace(/\/+$/, '');

export const str = (v, max = 5000) => (v == null ? '' : String(v)).replace(/\u0000/g, '').trim().slice(0, max);
export const oneLine = (v, max = 200) => str(v, max).replace(/\s*[\r\n\u2028\u2029]+\s*/g, ' ');
export const isDate = (s) => typeof s === 'string' && /^\d{4}-\d{2}-\d{2}$/.test(s) && !Number.isNaN(Date.parse(s + 'T00:00:00Z'));
export const dateOrNull = (v) => { const s = str(v, 10); return isDate(s) ? s : null; };
export const intId = (v) => (/^\d{1,9}$/.test(String(v)) ? Number(v) : null);
export const validEmail = (e) => /^[^\s@<>]+@[^\s@<>]+\.[^\s@<>]+$/.test(String(e || '').trim());
PLAIN ENGLISH

The public address of the site, with any trailing slash removed, so links in emails are built the same way everywhere. Falls back to localhost on a laptop.

 

str: turn anything into a clean string. Nothing becomes empty text, hidden zero characters are removed, spaces are trimmed, length is capped at 5,000.

oneLine: like str but capped at 200, and every line break, including unusual Unicode ones, becomes a single space. Names and subjects go through this.

isDate: accept only YYYY-MM-DD text, checked with a regex, that is also a real calendar date.

dateOrNull: clean the value, then return the date or null, never garbage.

intId: an id must be 1 to 9 digits and nothing else. Anything odd becomes null before it gets near a database query.

validEmail: a lightweight check that an address has something, an at sign, something, a dot, something, and no angle brackets.
